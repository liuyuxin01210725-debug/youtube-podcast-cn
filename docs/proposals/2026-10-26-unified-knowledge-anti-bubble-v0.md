# 统一生活知识与反信息茧房 v0

日期：2026-10-26  
状态：设计备忘。不授权实现，不改 studio 代码，不把个人痕迹写入本仓库。  
读者：HO鑫，以及下一个想把它做成系统的人。  
角色：对抗性架构。默认怀疑「再做一个知识图谱」会比什么都不做更糟。

相关现况（以本仓库为准，不按愿景脑补）：

- **studio** 是本仓库 `youtube-podcast-cn`。输入必须是带英文字幕的 YouTube。流水线是字幕 → 本地说话人 → DeepSeek / 通义千问翻译 → EdgeTTS 或千问语音。任务落在 `~/Desktop/音频/.podcast-jobs/<video_id>/`，其中 `metadata.json` 有 `video_id`、`source_title`、`webpage_url`、`channel`、`duration_seconds`，`state.json` 的 `phase` 停在 `translation_ready` / `transcript_ready` 表示译稿花了钱，不表示有人听过。成品 MP3 默认在 `~/Desktop/音频/`。没有 Whisper，没有文章转音频。
- **私人听** 只存在于 `docs/superpowers/specs/2026-07-14-ai-audio-mvp-design.md` 的项目 B：微信小程序里的私人播放库，`playback_progress` 计划有 `position_seconds`、`completed`、`updated_at`。本仓库没有这段代码。设计稿写明：没有真实收听数据之前，不做推荐。
- **三座 Obsidian 库保持独立。** 公开包测试 `tests/test_public_package.py` 禁止把健康向那座库的目录全名（「健康」紧挨「知识库」）和作者本机绝对路径写进仓库 markdown。本文只用角色名。磁盘真名只放本机 `vault-map.local.json`，该文件不进 git。
  - **K** = 卡帕西知识库。技术与学习的编译层。
  - **H** = 健康向库。身体、发酵、以及他自己从 SEEN 里用一句话写下的结论。
  - **W** = 工作知识库。决定、下一步、studio / 私人听的产品笔记。

## 判决

先做一张每周对账音频，再谈知识。统一视图是这张周报，不是第四个库，也不是一个兴趣图谱服务。studio 继续只做转换。Obsidian 继续只保存他亲口接受过的主张。私人听若还没被每天打开，就不准当数据地基。

Javis 三层草图里，值得留下的只有两句：半途收听不准自动入库；自动写库之前先有周报。其余两层（无摩擦全量痕迹、兴趣图谱当真相）应拒绝。理由见 §1.4，路线见 §8。

## 1. 问题重述与失败模式

### 1.1 要解决的两件事

HO鑫 同时做很多项目，执行跟进弱，听得进去、看不下去，英文材料要先变成中文播客才进得了日常生活。材料散落在 studio 的转换意图、私人听（若在用）、三座 Obsidian 库、Substack、SEEN、以及第三方播客应用里。

他要的不是一个更大的收藏夹，而是两件会互相拆台的事：

1. **生活知识能连起来。** 行为变成可回访的知识，形态接近 Obsidian / Karpathy 那种「原料与编译页分开」的 wiki。三座库继续分家。禁止用一个巨型库把工作、身体和技术吞进去。
2. **主动打破信息茧房。** 社交信息流会把同一类声音收拢。他要的是值得听的内容，经现有 studio 变成中文音频，并故意送上反面、盲区、相邻领域。搜索要多方向：热点、他正在追的问题、知识缺口、相邻方向（创业、商业、个人成长、健康、具身智能、发酵）。语气不能说教。

这两件事互相拆台：知识系统奖励「把已经相信的东西整理得更整齐」；反茧房要求「送上他没在追的东西」。合成系统若只有一个优化目标，一定会滑向整理，因为整理更像进度。

### 1.2 用户约束（设计必须吸收，而不是用提醒去对抗）

- 探索者，项目多。新系统本身会变成又一个开了头的项目。
- 跟进弱。任何「每天打开仪表盘回顾 10 分钟」的仪式，按不会发生来设计。
- 音频优先。文字周报的到达率按很低估计。周报的正文必须是中文音频。
- 英文障碍。发现结果的「为什么听」必须是中文。整集英文只在他点头之后才进 studio。
- 转换要花钱、要时间。未听完的成品是库存，不是学习成果。
- 三座库已经存在。再加一个「统一库」会制造第二座没人打扫的坟墓。

### 1.3 三种主失败，加上三种会伪装成进度的失败

**第二大脑坟墓。** 采集感本身像工作。链接着却从不点开，wiki 就只是更贵的书签。HO鑫 的历史行为（多项目、弱跟进）使这个失败的先验概率高于「图谱终于有人维护」。已有三座库。统一知识若再要求他维护第四套结构，坟墓会加倍。度量不是笔记篇数，是毕业笔记在 14 天内被再次打开的次数。这个数长期为 0，就停止毕业。

**吵闹的自动 wiki。** 半集、收藏、滚动、模型摘要，写成好像他已经相信的笔记。错误的库他不会搬。搜索一旦被半成品淹没，连原来能用的库也会废掉。Karpathy 式编译如果跳过人工验收，会变成语气肯定的噪音。提案收件箱本身也会变成坟墓：每周超过 1 条，他就不会判。

**推荐系统把茧房再造一遍。** 「因为你听过 X」会给出更多 X。这正是本设计要反对的目标函数。几种更隐蔽的版本：

- 只推荐「有英文字幕的 YouTube」。studio 的门槛会把发现锁死在英文科技访谈里，然后宣称这是在拓宽视野。健康、发酵、中文播客大量在这个门槛之外。
- 对抗车道固定投喂同一小群「反共识」名人。那是第二只茧房。
- 相邻领域变成比喻文：「发酵教创业者的五件事」。这是同一只茧房的文案。
- 热点接上社交信息流的 For You。他要躲开的就是这个收拢器。
- 个人成长内容看起来像多样性，实际上是同一类激励叙事换了主持人。

**未播放的转换被当成兴趣。** 转换摩擦很大，所以像强信号。对跟进弱的人，它经常只是「当时想成为会听完的人」。用它训练兴趣，得到的是人设，不是信念。

**问责剧场。** 周报生成了，没有第二个人注意到他没听。系统会礼貌地永久空转。提醒机器人不是问责。

**说教导致静音。** 一旦周报开始评价他这个人，他会关掉整个反茧房，连那一条真正有用的反面材料一起关掉。

### 1.4 对 Javis 三层草图的裁决

草图是：

1. 痕迹几乎无摩擦；
2. 兴趣图谱是 Javis 的真相；
3. 策展后的 wiki 毕业，写入「对的那座」Obsidian 库，写入前先提案。

P0 被写成：私人听 + studio → 每周注意力报告，并且禁止把每次半途收听自动写进 wiki。

**留下。** 「半途不准入库」是硬规则，本文加严，不放松。「先有周报，后谈写库」是整个草图里唯一正确的顺序。提案先于写入，方向对。

**拒绝第 2 层，兴趣图谱不是真相。** 从痕迹里长出来的图，编码的就是茧房。再称它为 Javis 的真相，等于把茧房写成制度。允许称为真相的只有两样：他亲手维护、最多 7 条、会过期的焦点卡；他明确接受、写进某一座库的笔记。推断出来的分布只配出现在当周周报上，下周重算，不落成服务。

**拒绝第 1 层当地基。** 「几乎无摩擦」采集的是最弱的信号（滚动、打开、收藏），却要打通最贵、最不可靠的接口。第三方播客应用没有义务提供事件。Substack 的阅读不是可导出的图。SEEN 的身体数据不该进同一个提示词。无摩擦痕迹还会诱导人把半途行为存下来，日后总有一个功能想用它们。P0 只读他已经留下的强痕迹：studio 任务目录里的标题、频道、阶段、文件时间。播放完成度在私人听真实上线之前，只来自他亲手打的标记。打不上标记就当没听完。少计比误计安全。

**第 3 层不是平台的下一阶段。** 「写入对的库」是未解的产品问题，不是图谱建完后的技术步骤。发酵可以像健康也可以像创业，具身智能可以像学习也可以像工作。分错一次，库就被污染，而他不会打扫。在看到提案接受率之前，写库不是路线上的必经点。周报音频本身就是产品。

草图还有一个依赖错误：把私人听和 studio 写成已经接好的一条数据平面。今天接好的只有 studio 的磁盘任务。P0 不绑定私人听。

## 2. 架构

### 2.1 原则

- 最小闭环优先于好看的图。P0 是一个本地脚本加一次语音合成，不是新应用。
- 每个数据源保持原职。studio 转换，私人听播放，Obsidian 保存已接受的主张，SEEN 留在 SEEN，Substack 留在 Substack，第三方播客应用留在原地。
- 统一只发生在每周那一页 / 那一条音频里。该页可丢弃、可重算。
- 默认拒绝。他没有回复「写」或「转」，就是拒绝，不是待办。
- 个人数据不进本公开仓库。账本、焦点卡、库路径、周报全部放在仓库外的本机目录。

### 2.2 组件

| 组件 | 是否已存在 | 职责 | 明确不做什么 |
|---|---|---|---|
| studio | 已存在，本仓库 | 他点头后，把合格的 YouTube URL 转成中文 MP3 | 不推荐、不读账本、不写 Obsidian、不保存兴趣 |
| 私人听 | 仅有设计，代码不在本仓库 | 播放与断点；上线后提供完成度 | 不是知识库，不做推荐算法 |
| `attention/` 本机目录 | 待建，且不进本 git | 焦点卡、账本、周报、提案 inbox、热点允许列表、库名映射 | 不是第四座 Obsidian 库 |
| K / H / W | 他已在用 | 唯一可以称为知识的地方 | 不接收未接受的文本 |
| 问责 | 人，或钱包额度 | 发现他跳过周报 | 不是聊天机器人人设 |
| 兴趣图谱服务 | **不建** | — | 见 §9 |
| 跨应用采集器 | **不建** | — | 见 §9 |

本机目录形状：

```text
attention/                      # 仓库外，私有
  focus-card.md                 # ≤7 个问句
  ledger.jsonl                  # 只追加
  allowlist.txt                 # 热点源，可空
  vault-map.local.json          # 三座库的磁盘路径，永不复制进仓库
  queue/YYYY-MM-DD.md
  reports/YYYY-MM-DD.md
  reports/YYYY-MM-DD.mp3
  proposals/inbox/
  proposals/accepted/
  proposals/rejected/
```

### 2.3 真相放在哪

| 问题 | 真相在哪 | 其他地方只是副本或视图 |
|---|---|---|
| 他声称正在追什么 | `focus-card.md` | 周报引用它，不修改它，除非他改 |
| 某次转换发生过 | studio 的 `metadata.json` + `state.json` | 账本只记指针和阶段，不复制逐字稿 |
| 有没有听完 | 他的显式标记；私人听上线后，`completed` 可覆盖「未标记」 | 磁盘上有 MP3 ≠ 听过 |
| 一条主张是否成立、住在哪 | 被接受的那座库里的那一页 | 周报和 inbox 都不是知识 |
| 本周倾斜多重 | 当周周报里的计数，当场计算 | 不写入长期画像 |

没有叫 Javis 的第四个真相。

### 2.4 数据流

P0，唯一先做的流：

```text
~/Desktop/音频/.podcast-jobs/*/metadata.json
~/Desktop/音频/.podcast-jobs/*/state.json
~/Desktop/音频/*.mp3 的文件名与时间
        │  只读标题、频道、时长、phase、路径。不读 transcript.zh.md
        ▼
attention/ledger.jsonl   ←  他用一行文字打的标记（可缺）
        │
        ▼
reports/YYYY-MM-DD.md     固定模板，P0 不调用大模型
        │
        ▼
现有 bin/tts-cn.sh --tts edge --style documentary
        │
        ▼
reports/YYYY-MM-DD.mp3    放到他下次本来就会打开的音频目录
```

P1 在 P0 的闸门通过之后才加：焦点卡 + 允许列表 + 账本 → 最多 5 条候选 → 同一份周报 → 他点头的 URL 才调用 `podcast-cn.sh`。

P2 在私人听真的在被使用、且他指定了唯一一座库之后才加：完成度写入账本；满足毕业门槛的事件最多产生 1 条提案；他回复「写」才向那座库追加一个小节。

P3 只是把已接受笔记的链接列进周报。仍然不建数据库。

### 2.5 一条作品的身份

规范 ID 是 YouTube `video_id`，或没有视频 ID 时的源 URL。私人听的 `episode_id` 若上线，必须能映射回这个 ID。Obsidian 来源卡使用同一个 ID。P0–P2 不做实体对齐平台。重名、同内容多平台，宁可不连，也不要猜错连在一起。

### 2.6 和本仓库的边界

实现未来若发生，脚本住在 `attention/`，通过子进程调用已安装的 `podcast-cn.sh` 与 `tts-cn.sh`。不把账本、库路径、发现爬虫放进 `youtube-podcast-cn`。本仓库的公开包测试和 README 已经把「个人知识库内容不进仓库」写成了不变量。这份备忘是设计，不是个人知识库正文；它也不包含逐字稿、密钥或库的磁盘路径。

studio 技能里已经证明：让代理重写整篇逐字稿会在长连接上失败，而且不该做。毕业摘录禁止读取 `transcript.zh.md` 全文。摘录最多 200 个汉字，且必须经过他接受。转换代理和笔记代理不是同一条管道。

## 3. 信号强度模型

要求的排序是：高摩擦转换 ≫ 听完 ≫ 半途 ≫ 收藏 ≫ 滚动。

这个排序描述的是 **意图有多费力**，不是 **信念有多可信**。两者必须拆开。对跟进弱的人，费力的意图经常没有消费。把未播放的转换写进兴趣，会建出人设图谱。

### 3.1 两套权重，禁止加总成一个概率

**意图（他伸手去拿什么）** — 只出现在周报的「你让系统干了什么」一节：

| 行为 | 意图强度 | 说明 |
|---|---|---|
| 转换请求：跑了 studio，任务目录出现 | 5 | 最高摩擦。他交出了时间和翻译额度 |
| 听完：显式 `done`，或私人听 `completed`，或播放比 ≥ 0.9 | 3 | 消费发生了 |
| 半途：播放比在 0.2 与 0.7 之间，然后离开 | 1 | 好奇，不是立场 |
| 收藏、稍后听、加队列 | 0 | 坟墓的标准入口。只记每周个数，不记成兴趣 |
| 滚动、曝光、打开不足 2 分钟 | 0 | 不存明细 |

**信念（什么可以影响下一周的种子，或什么可以提案）**：

| 行为 | 能否当种子 | 能否提案 |
|---|---|---|
| 显式 `useful` 或 `oppose` | 能 | 能，还要过 §6 的门槛 |
| 转换成功 **并且** 听完 | 能 | 能 |
| 听完，但没有转换（本来就是中文） | 能 | 能 |
| 半途 | 不能 | 不能。周报最多一行脚注 |
| 收藏 | 不能 | 不能 |
| 滚动 | 不能 | 不能 |
| 转换成功但没有播放证据 | **不能** | 不能。它只扣预算 |

不把这些数加权求和变成「兴趣分」。分层就够了：`Commit`（信念表里能当种子的）、`Sample`（半途）、`Spend`（花了钱没听完）、`Ignore`（收藏与滚动）。发现种子只用 `Commit`。`Spend` 只用在额度上。

### 3.2 播放比怎么定，避免假完成

P0 没有播放器事件。默认是 `Spend`，除非他写了一行标记。磁盘上的 MP3 不算听完。

私人听上线后：

- `ratio = position_seconds / duration_seconds`
- `completed = true` 时视作 `ratio = 1`
- 平均倍速 ≥ 1.8 且没有 `useful` / `oppose`：降为 `Sample`。背景磨完整集不算信念。这一条可以等到 P2，避免 P0 为了精确而拖延。

标记语法，一行一条，多了他就不会写：

```text
<video_id> done|half|drop|useful|oppose
```

`oppose` 表示「反对，但这条值得留」，它是反茧房的强信号，不是负分。`drop` 表示「不要同类再来」。`drop` 压低同一频道的重复推荐，不生成一条「他讨厌 X」的人格记录。

### 3.3 衰减与样本不足

- `Commit` 对发现种子的半衰期 21 天。
- `Sample` 不进入种子，脚注保留到下一份周报就丢。
- 焦点卡不自动衰减，但 `updated` 超过 30 天未被他确认，则失去权威：依赖焦点卡的车道全部关闭，周报仍可报告 studio 账目。
- 28 天内 `Commit` 少于 4 条：禁止宣布「倾斜」。样本不足就写样本不足。

### 3.4 什么根本不采集

第三方播客应用的滚动和播放、Substack 的星标、SEEN 的指标、微信聊天、浏览器历史。它们要么拿不到，要么拿到了也只是 `Ignore` 级。为 `Ignore` 建集成，是坟墓的施工图。

他若某周愿意，可以往账本粘贴一条 URL 并打上 `useful` / `oppose`。这是手工 `Commit`，合法。系统不去替他同步。

## 4. 发现引擎

发现不是信息流。它是每周最多 5 个槽位的候选表。槽位可以空着。空着优于注水。

### 4.1 焦点卡是唯一的「他说了什么」

```yaml
updated: 2026-10-26
questions:
  - id: q1
    text: 具身操作的上限，现在是不是由数据而不是算法决定？
    claim: 数据比新结构更决定上限。     # 对抗车道必填；没有 claim 就不能攻击
    tags: [embodied-ai]
    aliases: [具身, manipulation, robot data]
    vault_hint: K
```

规则：

- 最多 7 条。第 8 条写不进去。要加，先删。
- 必须是问句。单独一个词「AI」「健康」无效，该条不参与发现。
- 标签来自封闭集：`startup`、`business`、`personal-growth`、`health`、`embodied-ai`、`fermentation`、`other`。机器不准新开顶级类。
- 别名由他写。没有别名的标签不能做关键词匹配。不准靠模型猜「这句话是不是在说发酵」。
- P0 不自动打标签。未标记的 `Commit` 计入「听完了几集」，不计入倾斜。他不肯标记，倾斜就保持「样本不足」，对抗车道保持关闭。这是特性。

### 4.2 五条车道

每条候选固定四行，没有「点评」字段：

```text
lane: hotspot|focus|gap|adjacent|adversarial
title: （中文。英文原题可附在括号里）
url:
why: 一句中文，指出它回答哪一个 q
disputes: 一句中文，或「无」
bridge: 仅 adjacent 需要，一句机制，不是比喻
eligible: studio | listen-direct | link-only
cost: 大约分钟数；studio 则注明会花翻译额度
```

**热点 `hotspot`。** 只扫描他写在 `allowlist.txt` 里的源，种类只允许 `youtube-channel` 与 `substack-publication`，每类他自己给的 URL，总数不超过 10。每周取上次周报之后的新标题，不抓正文，不存全文。允许列表为空，则此槽永远为空。不接社交网络的推荐流。命中焦点卡别名的标题优先；完全命不中时，最多放 1 条「卡外标题」，且它不能变成后续种子。

**焦点 `focus`。** 在仍有效的问句里，选 21 天内 `Commit` 最少的那一条，找 1 个能正面回答它的源。YouTube 且能确认有英文字幕的，标 `studio`。已经是中文音频的，标 `listen-direct`。英文文章、论文、Substack 正文，标 `link-only`。P0–P1 不把文章整篇拿去 TTS。

**缺口 `gap`。** 焦点卡上的问句，21 天内没有 `Commit`，且 21 天内没有被他 `drop` 过同类候选。若与焦点槽选中同一问句，本槽留空，不重复。缺口只给 1 个起步材料，不给阅读清单。

**相邻 `adjacent`。** 同时满足才允许填槽：

- 两枚标签都在焦点卡上（他已经说自己在意，系统不替他培养新爱好）；
- 桥接句写出的是共享机制（测量、反馈、污染、数据成本、监管），不是「X 就像 Y」；
- 材料讲的是另一枚标签本身，不是跨界鸡汤；
- 两枚标签在他的 `Commit` 里共现比例 ≤ 0.5。共现更高，说明是同一簇戴了两顶帽子，不算相邻；
- 标题命中拒绝式：创业灵感、认知升级、人生功课、以及「像……一样」的比喻题。

`startup` 与 `business`、`health` 与 `fermentation`、`startup` 与 `personal-growth` 默认视为近义，不占相邻槽，除非桥接句指出一个可核对的具体主张（例如某家硬件公司的渠道成本），且他没有 `drop`。

**对抗 `adversarial`。** 触发条件，全部满足才欠 1 条，不是每周必填：

- 焦点卡未过期；
- 某问句带有 `claim`；
- 支持该 claim 的 `Commit` ≥ 3，且反对它的 `Commit` = 0；
- 28 天 `Commit` ≥ 4，否则样本不足，不触发。

材料要求：点名的作者或机构、一个正面论点、长形式。优先有英文字幕或已是中文音频。不收嘲讽切片。同一频道 6 周内不重复进入对抗槽。他最近 `Commit` 最多的 3 个频道不能充当「反面」，否则只是原茧房里的不同一期。

五条车道互相独立地产生草稿，最后用模板拼成周报。禁止一次模型调用「综合他这个人」再生成五条。健康类草稿不与创业或具身智能草稿放进同一个提示词。

### 4.3 从痕迹和陈述里看倾斜，同时避免说教

每周只算一张表，数字来自 §3 的 `Commit`，陈述来自焦点卡。28 天、按标签：

```text
标签            卡上有无    Commit 条数
embodied-ai     有          6
fermentation    有          0
...
最大占比        embodied-ai 6/8 = 0.75
样本            8（≥4 才允许读占比）
```

两种错配都写出来，不加形容词：

- 卡上有、28 天条数为 0；
- 条数占比 ≥ 0.75、卡上没有。

周报接着只问一个动作：「这条还要不要。不要就删。」他删了，对抗车道不再为它找对手。系统不自动补课，不用健康内容惩罚他这周全在听具身智能。

说教防护是机制，不是文风希望：

- 模板没有评论栏。
- 禁用词出现则整份散文作废，只保留数字表和候选四行。禁用词包括：你应该、认知偏差、信息茧房（用作对他的评价）、格局、本质、升维。车道名可以用「对抗」，因为那是槽位名，不是骂他。
- 对抗条目的 `disputes` 只能引用「它反对 q 的哪一句 claim」。
- 不存储跨问句的人格摘要，不写「用户是一个……」。
- 不从 SEEN 推断健康立场。健康车道只看焦点卡上他自己写的词。

### 4.4 预算：发现是特权，会自己关掉

- 每周最多批准 **2** 条进入「转换或去听」。其余候选 7 天后过期，不进待办。
- 对抗不额外加额度。它占 5 槽之一，也占 2 个批准名额之一，如果他选它。
- 上周每有 1 条 `Spend`（译稿或 MP3 已产生，没有听完证据），本周额度减 1，最低为 0。额度为 0 的那周，候选可以展示，转换按钮不出现。
- 连续两周周报音频没有播放证据：关闭全部发现车道，周报缩短为 90 秒账目（花了什么、没听什么）。
- 再连续两周仍没有播放证据：生成器停止，直到他手工跑一次。不提醒、不打卡、不写愧疚文案。

这是为弱跟进设计的收缩，不是惩罚循环。他不理它，它就回到今天已经存在的东西：他自己把 URL 贴进 studio。

## 5. 发现如何接上 studio 与私人听

### 5.1 先分流，再谈转换

studio 今天的能力边界是硬门槛，不是待优化项：没有可用英文字幕就不翻译；不跑 Whisper；不把网页和论文当输入；失败就不发布残缺 MP3；版权上只处理他有权转换的内容（README 使用边界）。

```text
候选
  ├─ 已是中文音频
  │     → eligible = listen-direct
  │     → 不调用 studio
  │     → 周报给出链接。私人听若已能播，再上传；否则他用现在的播客应用听
  ├─ YouTube，且探测到可用英文字幕
  │     → eligible = studio
  │     → 只有他当周点头才运行 podcast-cn.sh
  ├─ YouTube，但没有可用英文字幕
  │     → 丢弃，周报写「字幕不够」
  └─ 英文文章、Substack 正文、论文
        → eligible = link-only
        → 一句中文 why，不整篇合成
        → 文章转音频是另一份设计（2026-07-14 已明确推迟），不塞进本备忘
```

因此反茧房 **不允许** 被 studio 的门槛绑架。健康、发酵、中文播客可以占槽，它们只是不进转换器。若五条里能听的全是英文字幕科技视频，周报要在表上显示「本周 studio 合格源的标签分布」，让这只衍生茧房可见。可见即可，不自动改配额。

### 5.2 点头之后的调用

不新增 studio 参数，不改本仓库。形状就是现有命令：

```bash
bash bin/podcast-cn.sh "$URL"
```

语音默认 Edge。只有他在标记里写过这条源「值得重听」，才允许 `--tts qwen3-api`。发现试点用千问语音，成本会劝退整个闭环。翻译供应商沿用他的默认（DeepSeek），周报不替他升级模型。

点头的记录是账本里的 `convert_request`，发生在进程启动之前。这样「他批准了但脚本失败」和「他没批准」可以分开。

不预下载候选的音频，不预抓全文，不预翻译。候选表只留标题、URL、车道、两句中文。

### 5.3 私人听的位置

私人听上线前：成品留在 `~/Desktop/音频/`。周报不声称「已经在微信里」。2026-07-14 的成功定义（每周至少三次用于通勤、走路或健身，且不用手工传文件）仍然有效；在那之前，发现系统不得假设播放数据存在。

私人听上线后，同步是单向的：

```text
playback_progress → 每天最多一次 → ledger 的 play_progress
```

私人听仍是播放位置的真相。账本不回写进度，避免两个写入者。上传沿用设计稿里的幂等上传（校验和相同则不建重复集）。自动上传可以被关掉，关掉后发现系统继续工作，只是没有 `ratio`。

播放器里的排序规则，也是交付的一部分：当周批准的音频放在列表最前。周报音频不和一部新成品挤在同一天——周报放在没有新成品的那一天。日报如果和新集竞争，他会两个都跳过。

### 5.4 中文「为什么听」从哪来

P0 周报没有发现散文，也不调用大模型：标题用 `source_title`，数字用文件时间与 `phase`。  
P1 的两句中文来自一次小调用，输出必须符合 §4.2 的四行，输入只有标题、频道、问句 ID 和 claim。不把英文字幕送进这次调用。调用失败就留下英文标题并标 `why: 未生成`，不阻塞账目音频。

## 6. Obsidian 路由与 Karpathy 式编译纪律

Karpathy 公开讲过的做法，这里只取纪律，不假装他规定了目录格式：原料保持不变；wiki 是编译结果；ingest、query、lint 分开；人看过才生效。下面的目录是 **本设计** 的布局。

查询不是产品。他要找，就在 Obsidian 里搜。不做一个聊天机器人当第二大脑。聊天记录不是知识。

### 6.1 三座库各干什么

**K，卡帕西知识库。** 概念页。适合具身智能、论文、工程主张。

```text
raw/sources/<id>.md     # 不可变来源卡
wiki/<concept>.md       # 主张、引用、矛盾
```

来源卡字段：规范 ID、URL、日期、标签、`support|oppose|orthogonal`、他接受过的不超过 200 字摘录、指向 wiki 页的链接。没有摘录就没有来源卡。

**H，健康向库。** 日期实验笔记，不是百科，也不是方案库。SEEN 的数字留在 SEEN。他若要记，只记他自己写的一句结论。每条笔记第一行固定为：`未验证的个人笔记，不是方案。` 发现引擎的健康内容禁止自动收成「协议」。发酵默认来这里；只有他在批准时改选，才能去 W 或 K。

**W，工作知识库。** 一条决定一个文件：日期、决定、理由、下一步、回顾日。没有下一步的笔记不进 W。studio 与私人听的产品决定放这里。知识性长文不进 W。

### 6.2 路由顺序

正文只住一座库。另一座库最多留一个指向规范 ID 的链接，不复制正文。

1. 他在批准转换或批准提案时指定的库。
2. 否则用该问句的 `vault_hint`，且标签与 hint 一致。
3. 否则用下表。冲突或落在「无默认」→ `proposals/inbox`，不写库。

| 标签 | 默认 |
|---|---|
| `embodied-ai` | K |
| `fermentation` | H |
| `health` | H |
| `business` | W，且必须有下一步，否则 inbox |
| `startup` | 无默认 |
| `personal-growth` | 无默认。不写，除非他指定 |
| `other` | inbox |

创业同时像学习和像工作，所以没有默认。个人成长最容易把鸡汤写进 K，所以默认不写。这个保守会漏掉笔记。漏掉是对的。

### 6.3 毕业门槛

全部满足，才允许在当周周报里出现 **1** 条提案。一条都不满足，周报的提案节就写「无」。

- 事件是 `Commit`（听完，或 `useful` / `oppose`）。半途、收藏、滚动、未播放的转换，不提案。
- 能写成一个主张句。
- 能指向一个已有概念页，或一个他给出的新概念名。新概念名每周最多 1 个。
- 摘录不超过 200 个汉字，且他接受过。摘录不是模型对全文字幕的摘要。
- 路由无冲突。
- 若去 H，第一行是未验证声明。若去 W，有下一步。

提案格式：

```text
target: K|H|W
target_note: 已有路径，或 NEW:<名字>
claim: 一句话
source_id:
stance: support|oppose|orthogonal
contradicts: 可选，已有笔记的名字
extract: ≤200 字
action: 仅 W 需要
```

他回复「写」：脚本在目标笔记末尾 **追加** 一个带日期的小节，不改写旧段落。  
他回复「停」，或 7 天没有回复：记 `rejected`，同一 `source_id` 90 天内不再提案。沉默是拒绝。inbox 不保留「待以后再看」。

lint 每四周最多一次，而且只在他当周听了周报之后，作为下一周的那 **唯一** 一条提案：孤儿页、没有来源的主张、与新摘录矛盾。lint 不自动改页。

### 6.4 和「统一图谱」的关系

跨库的「图」就是来源卡上的规范 ID，加上周报里列出的「本周接受了什么、住在哪」。不把三座库同步进一个索引服务。不把 H 的正文送进 K 的编译提示词。身体笔记和工作笔记不要在同一次模型调用里「打通」。

## 7. 真正会跑的循环与外部问责

### 7.1 每日

没有每日回顾仪式。每日唯一的规则是投放：

- 新批准的成品出现在播放列表最前，或出现在 `~/Desktop/音频/` 里他已经会看见的位置。
- 周报不占据新成品的那一天。
- studio 失败时，沿用现有命令的错误输出。不另做一条「每日健康检查」音频。

如果某天的设计需要他打开一个新的界面，这一天就不存在。

### 7.2 每周：收听对账

固定一天，本机脚本在他的电脑上跑（电脑睡着就下次开机补，不为此上服务器）。P0 不调用大模型。语音用 Edge、`documentary`，8–12 分钟；发现关闭后的收缩版约 90 秒。

模板，顺序固定：

```text
# 注意力对账 YYYY-MM-DD
## 账目
翻译到 transcript_ready 的集数、产出 MP3 的集数、有听完证据的集数、估算上「花了但没有听完证据」
## 完成
有 Commit 的标题，每条一行
## 焦点卡
updated 日期。过期则说「焦点卡已停用，发现关闭」，并逐条读出问句，问他保留还是删除
## 倾斜
§4.3 的表。样本不足就说样本不足
## 候选
最多 5，每条四行。P0 此节为「无」
## 提案
最多 1。P0、P1 此节为「无」
## 额度
下周可批准的条数（2 减去本周 Spend，最低 0）
```

他的回应也固定，且可以缺省：

- 改焦点卡：自己改文件。不改 = 维持；超过 30 天不确认 = 停用。
- 批准转换：回复 `video_id yes` 或把 URL 发回。没有这条回复，脚本不跑。
- 打标记：§3.2 的一行。没有 = 未听完。
- 入库：回复「写」或「停」。没有 = 停。

### 7.3 外部问责

弱跟进的人无法用自我回顾当控制系统。二选一，由他定（§10）。在他定之前采用钱包，不采用虚构的伙伴。

**人。** 每两周一次，10 分钟。对方的全部工作是三句话：上周批准的两集听完了没有；这周批准哪两集；焦点卡里哪一条是空的。不讨论笔记系统。连续两次他不出现，对方只说「发现先停」，系统按 §4.4 收缩。找不到愿意说这句话的人，就不要假装有人。

**钱包。** 没有人时的唯一问责。每周硬上限、未听完扣减、月翻译额度他自己封顶。周报必须念出「有译稿或有 MP3、没有听完证据」的条数。不建催促机器人。催促会被静音，然后连账目一起消失。

问责检查的是闭环有没有跑，不是他有没有变成更好的人。

## 8. 路线、杀死条件、单独价值的概率

概率是「做到这一阶段就停，它自己值不值」的主观估计，不是条件概率。依据是：跟进弱、音频才到达、本仓库还没有私人听、三座库已经足够让人分心。

| 阶段 | 单独交付什么 | 单独就有价值的概率 | 为什么不是更高 |
|---|---|---|---|
| P0 账目周报音频 | 看见转换与听完的差距，额度开始反映未听完 | **0.50** | 音频若没送进他已经会打开的地方，概率降到约 0.15 |
| P1 五槽发现 + 人工点头 | 有些周多听 1 条原本不会听的；其中有时是反面 | **0.30** | 发现质量一般；跟进弱时队列会变成新的内疚清单 |
| P2 单条提案入库 | 三个月后能在指定的那座库里点回某条主张 | **0.20** | 他可能不回访。不回访的毕业就是新坟墓 |
| P3 周报里的链接页 | 在 P2 的笔记之上多一个跨库索引 | **0.10** | 没有回访习惯时，索引是坟墓的目录 |

预期价值集中在 P0。先做 P2 或 P3，单独价值接近 0。

### P0 — 账目镜像

范围：读任务目录的 `metadata.json`、`state.json`、MP3 是否存在；合并他可选的一行标记；填模板；Edge 合成。零模型调用。零写库。零爬虫。不读取 `transcript.zh.md`。

进入 P1 的闸门（全部满足）：

- 连续 4 周里至少 3 周，周报音频有播放证据（标记，或问责人确认）；
- 至少 4 次显式标记（说明他肯用那一行字，而不是只生产音频）；
- `Spend` 不超过当期成功转换的一半。

杀死：

- 连续 3 次周报没有播放证据 → 收缩为 90 秒，发现保持关闭（此阶段本就关闭）；
- 再连续 2 次没有播放证据 → 停止生成，回到纯手工 studio；
- 他连续 4 周仍在转换、听完证据为 0 → 不杀死周报，把批准额度打到 0，周报只报库存。

P0 被杀死不视为技术失败。视为假设「他愿意听一张对账音频」不成立。之后不做 P1。

### P1 — 发现队列

范围：§4 的五槽。热点与对抗在允许列表或 claim 缺失时保持空槽。他点头才转换。仍零写库。

杀死：

- 4 周内被批准的条目，听完率 < 0.3；
- 或对抗槽被 `drop` 的比例 > 0.7，且他没有改 claim（对抗在打空，关闭对抗，保留其他槽再观察 2 周；仍然打空则退回 P0）；
- 或额度按规则归零的周数 ≥ 3。退回 P0，保留账目。

### P2 — 提案

前提：私人听的 `playback_progress` 已经在他的真实听音路径上，**或** 他明确接受「只有手工标记算听完」并已经在 P0/P1 里打过标记。他必须指定第一个月唯一接收毕业笔记的那座库（§10）。未指定则不做 P2。

范围：每周最多 1 条提案，沉默即拒绝，只追加不改写。

杀死（永久，不自动重开）：

- 4 周接受率 < 0.2；
- 或接受后 14 天内被他删除或移出的比例 > 0.5；
- 或他标记「库错了」达到 2 次。

杀死之后，提案节永久为「无」。不降级成一个慢慢堆积的 inbox。

### P3 — 链接页

范围：当周周报增加一节，列出已接受来源卡的规范 ID 和所在库。不建图数据库，不做向量检索，不做跨库 RAG。

杀死：该节连续 30 天没有被打开（Obsidian 的打开，或他在问责里引用过其中一条）。立即删掉这一节的生成。已接受的笔记留在原库。

### 8.1 现在不要排期的东西

文章 / 论文 → 音频、Whisper、公开电台、多用户、推荐算法进私人听、自动打标签、自动写库、SEEN 连接器、Substack 全文存档、第三方播客 SDK。每一项都有自己的产品假设，夹进本路线会让 P0 永远不开始。

## 10. 只有 HO鑫 能回答的问题

回答之前，P0 仍可按本文默认值启动：没有问责人、每周上限 2、未听完 1:1 扣减、听完只认手工标记、对抗与热点关闭、写库关闭。P1 的对抗槽、P2 整体，会停在这些答案上。

1. **谁负责发现你没听周报？** 给出一个真实的人，并确认对方愿意只问 §7.3 那三句；或者明确说没有这个人，钱包额度就是唯一问责。不要回答「做一个机器人提醒我」。

2. **过去 14 天，听完的那几集是在哪听的？** 私人听、桌面上的 MP3，还是某个第三方播客应用。只能指定一个作为「听完」的真相来源。另外两个里的播放，系统当作没看见。

3. **第一个月，哪一座库接收唯一的毕业笔记，那个问句是什么？** 只能是 K、H 或 W 里的一座。问句必须是一句可反对的话，不能是一个领域名词。不回答，P2 就不存在。

4. **每周转换硬上限是几？未听完要不要扣？** 建议上限 2，每条 `Spend` 扣 1。需要的是一个你愿意被系统强制执行的数字，不是「看情况」。

5. **写出一条你现在愿意被攻击的主张。** 创业、健康或具身智能里的一句完整判断。写不出，对抗车道保持关闭——没有主张的「反面」只是随机唱反调。
