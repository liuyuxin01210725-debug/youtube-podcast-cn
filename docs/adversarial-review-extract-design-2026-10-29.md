### 开干前必须补进规格（5）

1. **时间参照系。** `t_start` / `t_end` 必须是手机正在播的 `output.mp3` 轴：口播广告已掐掉、中文合成片段按拼接顺序累加之后的偏移。源字幕 `start_ms` 只允许留在 Mac 侧映射里。映射不出来的条拒收，不许改记成源片时间。`span` 绑定译稿句子；外文专名必须是该句或对应源句里的子串，禁止补全未说出的书名和 URL。
2. **收藏手势的时序（不改 Q1）。** 点收藏 = 把该集 deep 任务入队，不是只改布尔。无「可对齐译稿 + 成片时间映射」时，行内只显示「先听译」，不出现已收藏成功态。无透镜时用「通用」，不另跑分类模型；节目名能对上 `lenses.json` 才预填 schema。改 schema 走已拍板的手动提炼，计入 24 小时重跑。任务还在 `queued` 时取消收藏 = 撤销，不扣模型。
3. **听完 light 不进待确认。** light 只留一行 `summary_line` 和折叠名录，不生成须逐条确认的卡片，不占「N 条待确认」，不把 Q2 的 Inbox 门槛（待确认 ≥20）提前打穿。待确认只来自 deep / manual 的必抽槽。
4. **状态机落盘，且跳转不写续听书签。** Packet 与每条 `status` 跟 episode id 存在资料库里单独的 `extract.json`（或等价文件）。再次发布 `episode.json` / `output.mp3` 时合并保留确认、丢弃、动作态，禁止整文件覆盖把库清掉。Markdown 从这份状态导出。「跳回原句」只移动播放头；`ListenMark` 仍只由播放进度写入。听完判定沿用现有「距结尾 15 秒」，不因此把 light 送进确认队列。
5. **健康 / 投资卡的主按钮语义。** `health` 的 Method 主按钮用「仅记录」，不用「待实践」。免责短句贴在该按钮旁（非诊断、非处方），不放页脚。剂量、频率、动作对不齐 span 或置信 &lt;0.5 则丢弃，不折叠展示。`biz_invest` 的卡片主视觉不出现「看多 / 看空」；Org 保持「观察候选」。两条都不做跟买、跟练、涨跌提醒。

### 最狠的三个洞

1. **页首「已定」写成了能力，库里没有抽。** 菜单还能看见「设计」二字；进页后标题是「收藏≠拥有」，callout 写「收藏 = 深抽」「声间内库 + Markdown 导出」。`LibraryStore` 没有收藏字段，`PlayerView` 没有提炼区，发布物没有稿。这是假交付，比假收藏更靠前一步：用户（或下一棒实现）会以为闭环已经在 App 里。
2. **规格里的时间戳不是用户听到的那条轴。** 中文稿渲染只留段 id 和译文，不写时间（`podcast_cn.py` 的 `_render_chinese_transcript`）。成片合成会丢掉 `is_ad` 段且不补静音，再按中文配音长度拼接（`studio_engine.py` `render`）。手机只收到 `output.mp3` + `episode.json`。按源片 `start_ms` 去 seek，跳不到原句。span 约束会变成另一层幻觉。
3. **Q1 × Q2 ×「听完就静默 light」会在 Inbox 被禁止出现之前把确认打爆，同时「深抽前可改 schema」把「收藏即抽」拆开。** deep 上限约 44 条，每条确认 / 丢弃 / 主按钮。light 若也算待确认，两三集听完就越过「≥20 再做 Inbox」。无透镜时规格又要求深抽前让用户改 schema——那一次确认若挡住模型，收藏就不是深抽；若挡不住，发酵集会被抽成通用摘要。

## 第一轮 · 规格自攻

按上传稿本身打。景观只用来核对：这些坑作者已经看见，对策有没有写到可执行。

### 假收藏

F1 的对策是「星标 = 深抽任务；无稿则阻断并引导听译」。叙事成立，时序不成立。

- 三个手势被 P1 写成同一件事：星标、收藏、「提炼」。Q1 又把手动提炼留成「改 schema 重跑」。实现时会出现两颗按钮。点错一颗，要么空转布尔，要么 24 小时内第二次 deep 被 G4 吞掉，用户以为在改 schema。
- 「已收藏」如果先于任务写进 UI，无稿阻断就来不及。规格没有说成功态必须等 `queued` 出现。假收藏会从「只有星」变成「星了，但提炼中永远不结束」。
- 取消收藏、重复收藏、听完后再收藏，都没有迁移表。deep 已 `ready` 时取消，包是删、是 `stale`，还是留着继续占待确认，三读都说得通。

### 噪音

禁长摘要、一行 `summary_line`、条数上限，这三刀对准了 Listen411 / 小宇宙式泛摘要。漏的是 light。

听完即静默 light，且 light 含最多 3 条 Claim。Claim 的定义是「可辩论主张」，模型默认会交剧情句。用户没点收藏，详情里已经有一批「像知识」的句子。这和「收藏才是抽取入口」并列存在，噪音从后门进来。

多主题「次透镜只抽必抽且封顶」没有给出封顶数字。G2 是整包上限，不是次主题上限。发酵+投资的一集会把两套必抽都塞进同一 44 条里，F11 的对策不可执行。

### 幻觉

强制 span、低置信、禁止编 URL，方向与景观 §4.2 一致。门槛写松了。

- 「低置信或拒收」在 §3.4 变成折叠。折叠仍渲染，投资公司和健康剂量会以灰色卡片留下来。
- ≥8 字只证明「附近有一句人话」，不证明实体名被说出。
- 中文译稿是用户读的文本，源字幕才有 `start_ms`。规格没指定 span 的字符串必须命中哪一份。外名保留和中文 span 很容易各写各的。
- 广告：工作室已经用 `is_ad` 整段不合成。规格 G7 仍写「若有 chapter 标签则跳过」，好像广告还在成片里。抽取若吃源字幕，赞助商会进 Entity；若吃成片译稿，广告已不在，却可能被模型按记忆补回。两条都是幻觉路径。规格要写：抽取输入 = 已去掉 `is_ad` 的译稿段，与成片同一清单。

### 成本

分档、无稿不深抽、每集每日一次、额度可见，都比 Snipd 把额度当叙事要干净。门是松的。

- 输出条数有顶，输入没有。一集数小时译稿一次结构化调用，成本在进模型之前就发生。
- G5 写「自用可先松」。个人工具仍是账单。误触收藏没有撤销。
- G6 依赖不存在的质量分。实现者会用「有稿」代替「稿可用」，烂 ASR 仍深抽，F8 落空。
- §3.3.2 的轻分类是收藏之外的另一次模型。无透镜的库（今天全部单集）每集深抽前都可能先分类一次。

### IA 极简

P6、§5、§5.4 把新 Tab 和空广场禁住了，阅读器也确实没新开 Tab。冲突在已有表面上。

- 「一池 + 智能芯片」描述的是发现页的透镜条。资料库是纯列表。抽取徽标要加在没有芯片的那一池上。
- 发现页透镜过滤的是预置 show，含空透镜。规格写「透镜只筛已拥有」。两套「透镜」同名不同物。抽取 schema 映射若读发现目录，会把「可关注的节目」当成「这一集的主题」。
- 附录 B：待确认 &gt;0 就可以出状态芯片。§5.1 又说芯片是后续、有货才出现。MVP 到底出不出芯片，两处都能引用。

### 确认疲劳

全路径「抽出 → 候选 → 确认 → 才入队」是对的，用来挡住自动关注。疲劳来自粒度和重复。

- 44 条 ×（确认、丢弃、主按钮）。Person/Show 的主按钮没有改变状态（已经是 candidate），等于多一次空操作，然后再确认才关注。
- Q2 把批量收件推后。疲劳没有出口，只能在单集里点完。
- light 若计入同一队列，用户会先为「没收藏也要确认」疲劳，再为收藏疲劳。
- 规格没有「本集其余丢弃」以外的批量，也没有「低置信不出现」。一键丢弃写在 F3，没有写在 MVP 卡片上。

不把批量 Inbox 拉回 MVP（那会改 Q2）。把待确认的集合缩小（第 3 条）才是不越界的减负。

### 健康与投资误导

F13 有一行对策：免责短句、可丢弃、不自动跟买跟练。产品结构在反着做。

- 健康必抽的是带剂量和频率的 Method，默认动作是待实践。这就是一份可执行方案，免责若在页脚，按钮已经完成误导。
- 发酵 Method 也带温度、时长、剂量。schema 判错时，补剂剂量和工艺参数会互换槽位。无透镜默认「通用」至少不会把剂量标成必练；轻分类判成 health 则会。所以第 2 条坚持无透镜用通用，而不是先分类再深抽。
- 「看多 / 看空」是交易口气。放进字段就会进 UI。观察名单可以留，立场词不要当主视觉。
- 发酵章的 `productizable=true` 只是标签，纪律写了不立项。实现时不要给这个标签做入口。本审查不把它升成 P0。

## 第二轮 · 规格 vs PR#19

### 设计页是不是假交付

是阅读能力，不是抽取能力。代码注释写明 founder-facing spec reader，不是 Tab，也不是市场页。PR 正文同样把范围限制在设计页和续听。

假交付出在完成态文案和验收误读：

| 规格 MVP（§5.1 / §10.1） | PR#19 实际 |
|---|---|
| 收藏触发 deep | 无星标、无收藏、无任务 |
| 无稿阻断 | 手机条目无稿指针；发布不拷贝译稿 |
| 行内「提炼中 / N 条待确认」 | 只有「未听 / 已听完」 |
| 详情折叠区「提炼」：跳转、确认、丢弃、主动作 | 导航终点是播放器，没有折叠区 |
| Person/Show 候选门闩 | 无实体 |
| 声间内状态 + Markdown 导出 | 导出的是把规格 Markdown 装进 App，不是导出抽出物 |
| 听完静默 light | 听完只把 `ListenMark.finished` 设为 true |

页顶 callout 把 Q1、Q3 读成已在这个屏幕生效。菜单名带「设计」，标题把「设计」拿掉了。下一棒若只「把按钮接到这个已定页面」，会在阅读器上加星标，而星标下面没有状态机。那就是 F1 的成品。

本审查不要求拆掉阅读页（它不新开 Tab，也没进发现）。要求规格和后续 PR 把它排除在「抽取已交付」之外。

### 续听和抽取状态机会不会打架

现在没接上，所以还没在运行时打架。接上就会打架。续听这一笔本身是清楚的：

- 进度在手机 `UserDefaults` 的 `PrivateListen.progress`，按 episode id，不写 iCloud。
- 未听：无记录，或 &lt;5 秒且未完成。
- 上次听到：未完成且 ≥5 秒。列表有文字和比例条。
- 已听完：时长 &gt;1 秒且播放头在结尾 15 秒内。下次 `resumeSeconds` 返回 0，从开头播。
- 播放器暂停在中间时显示「继续听 · 时间」。距结尾 ≤15 秒或播放头 ≤5 秒则不显示。
- 打开时先把界面停在断点，seek 落地前不把进度写成 0。

规格里的 `Work.progress`（未听 / 在听 / 听完）和这个书签不是同一个字段。听完触发 light，用的应是「已听完」这次跃迁，而不是「进度大于 0」。规格没写跃迁只触发一次。现在的 `remember()` 会在用户从开头重听时把 `finished` 写回 false。若 light 挂在这次写入上，重听会反复入队或反复清掉「听完」。

更硬的冲突是 seek：

- 跳回原句若调用现有 `seek(to:)`，完成回调里会 `checkpoint()`，续听点变成金句时间。
- 「继续听」字幕读的是当前播放头。跳完若暂停，字幕会把金句位置说成「继续听」。
- 列表「上次听到」同步说谎。

听完的 15 秒和继续听消失的 15 秒是同一刀。可以继续当播放语义。不可以当抽取语义的唯一输入：人在结尾前 20 秒暂停，仍是「继续听」；再听几秒变成「已听完」并从下次开头播。light 若在这一刀上烧模型，边界来回拖就会重复扣费。第 3 条让这一刀只影响播放，不影响待确认。

播放进度与知识状态不要共存在一个 `ListenMark` 里。续听继续留在 UserDefaults。抽出物按第 4 条进资料库文件，否则重装手机丢「第一知识库」，Mac 也导不出 Markdown。

## 风险（点名，不推翻）

- **Q1** 仍是收藏 = 深抽。风险是深抽前的 schema 对话框和「先写星、后接线」会把它做回假收藏。用入队 + 默认可抽取来守，不用第二颗「真正抽取」按钮来守。
- **Q2** 仍是单集详情。风险是 light 与 deep 共用待确认计数，详情装不下，有人会借「≥20」把 Inbox 做进 MVP。缩小待确认集合，不提前做 Inbox。
- **Q3** 仍是声间内库 + Markdown。风险是库若等于 UserDefaults 或等于会被发布覆盖的 `episode.json`，导出没有稳定真相。单独文件、发布时合并。
- **禁新 Tab / 空发现。** 发现 Tab 和空透镜已经在 PR #18。抽取工作不去填它，也不新开知识 Tab。阅读器放在资料库「更多」符合「不新开 Tab」，但不要再占用成唯一二级能力。
- **禁 Chat P0、禁自动入队。** 规格这两条写死了，本轮没有发现要推翻它们的新证据。Person/Show 主按钮不要做成关注。
