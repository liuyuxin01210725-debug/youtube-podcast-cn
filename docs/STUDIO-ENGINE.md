# Studio engine contract

Run `.venv/bin/python scripts/studio_engine.py --job-dir /absolute/job --config /absolute/config.json [--action prepare|render|run] [--preview 3] [--accept-unreviewed]`.
The caller must serialize runs per job and serialize ML jobs globally on a 16 GB Mac. Use an absolute owned job directory. No HTTP server is introduced here.

Config (credentials must never be in this file):

```json
{"source":{"kind":"local","value":"/absolute/English.wav"},"provider":"deepseek","tts":"edge","speaker_count":2}
```

Use `source.kind=youtube` and the exact video URL. Optional `tts` is `edge` (default), `clone`, or `qwen3-api`; `style` is `conversation` or `documentary`. Optional `clone_model`, `asr_model` override defaults. Official defaults resolve pinned, already downloaded HF snapshots, with no model network downloads during jobs. `.speech-venv/bin/python` runs MLX; legacy `.venv` runs the orchestrator, `.diarization-venv` remains managed by the existing runtime. Translation credentials resolve environment then the existing macOS keychain service/account; never pass keys via arguments.

`prepare` writes `document.json` without synthesizing. `run` prepares if needed then synthesizes; `render` reuses a prepared document. Render never retranslates edited Chinese text. To change source/translation provider, create a new job or explicitly run prepare. A job's source is immutable by caller contract. `--preview N` asks `select_preview_segments` for up to N lines: the longest Chinese line of each speaker in document order, then padding only if N is larger than the speaker count. The workbench sets N to `min(distinct speakers, 5)`. A hand-passed `--preview 3` is three lines, not "the first three segments". The full export is `output.mp3`.

Document schema version 1 contains `segments` (stable id, start_ms, end_ms, English `text`, editable `chinese`, editable `speaker_id`, `ambiguous`), `speakers` (id -> editable voice_slot), `references` (speaker id -> path, sha256, exact matching English text/start/end), and transcript_source. Source references are derived only from unambiguous complete cues wholly inside a single speaker turn without overlapping other speakers. Missing clean reference stops cloning with an actionable message; no invented speaker identity or automatic fallback. UI may let users replace a reference with another job-owned WAV and matching English text. Paths are validated to remain within the job.

Every segment cache key fingerprints Chinese text, speaker voice settings, model/backend fingerprint and reference bytes/text. Audio must decode before reuse. Changing one segment/reference only regenerates affected audio. Complete MP3 is atomically published after every selected segment and final export validate; prior output remains intact on failure. `audio-cache/`, `translations/`, `references/` persist for resume. References are explicit persistent voice samples; `temporary/` contains source/ASR media and is always removed on success, failure or cancellation. Caller should offer deletion of the whole job to remove reference samples and caches.

`progress.json` is atomic: stage, completed, total, updated_at, stage_started_at, optional eta_seconds / subtitle_fallback_reason / segment_id / output / message. Stages: transcript, diarization, asr, translation, synthesis, export, complete, failed, cancelled. The UI message is `user_facing_message`: `StudioError`, `StudioInputError`, `PodcastPipelineError` (including a missing API key name), `TTSBackendError` (including the Edge 403 upgrade hint), and exception types whose names start with `Diarization`. Text that contains `http(s)://`, a Bearer token, or `token=` stays the generic failure sentence. Other exception strings stay in `debug-failure.json` only. Translation requests use existing bounded retries; cancellation is checked between requests. Edge/Qwen API calls may finish the current network request before cancellation completes.

Cancel by creating `job/cancel` or SIGTERM/SIGINT. Remove `cancel` before resume. Child process groups are terminated and source temp media cleaned. Exit 130 cancelled, 1 failed, 0 complete. Never SIGKILL the orchestrator if cleanup is required. Export concat uses file-backed ffmpeg inputs; whole-episode PCM is never held in Python RAM.

ASR uses fixed 60 second local chunks and absolute timestamps. A word crossing a hard boundary may be less accurate; this release does not claim a word-perfect transcript. Subtitle-first acquisition falls back to local ASR when English tracks are unavailable/unusable. Diarization remains mandatory. Alignment still leaves a cue unassigned when the nearest turn is more than 1500 ms away. Studio then runs `fill_unassigned_for_review` only after the 20% unassigned gate: that cue is attached to the nearest existing speaker and marked `ambiguous`. It is not used as a clone reference. A render that does not pass `--accept-unreviewed` still refuses every selected segment that is ambiguous. The workbench can clear every flag in one step (`POST /api/jobs/<id>/confirm-speakers`, 「全部按当前说话人确认」) or synthesize anyway (`--accept-unreviewed`, 「带风险继续」) while leaving the flags in place. Saving Chinese text no longer clears those flags; changing one segment's speaker clears only that segment. CLI `prepare_episode` still rejects any unassigned cue. More than 20% unassigned cues still abort before the fill.

Terminal failures retain `failed_stage` and a bounded `error_code` (`source_access_denied`, `network_unavailable`, `model_missing`, `dependency_missing`, `invalid_input`, `process_failed`, or stage-specific failure). Only recognized stderr patterns map to fixed actionable Chinese messages; raw subprocess/provider diagnostics never enter progress. YouTube 429/login failures suggest waiting or importing an already downloaded local file. Private, unavailable, and age-restricted videos use the same `source_access_denied` code with a fixed Chinese sentence. No browser-cookie or keychain-permission automation is performed. A missing ffmpeg (`dependency_missing`) is not reported as invalid audio. A clip ffmpeg cannot decode is still treated as a bad cache entry and regenerated.

Reference generation uses full original VTT cues independently of rolling-caption deduplication used by translation; overlapping raw cues are never concatenated into repeated reference text. New studio documents assign system voice slots with `assign_studio_voices` in first-appearance order: `male_1`, `male_2`, `male_3`, `female_1`, `female_2`. These are synthesis presets, not inferred identities or genders. The order is male-first so the first speaker in an interview is not `female_1`. CLI `speaker-map.json` still uses `VOICE_ORDER` (`female_1` first) and is not rewritten. The five-slot pool cycles if more speakers are present (a sixth reuses `male_1`) and stays user-editable from the speaker dropdowns, which are saved with the transcript. `POST /api/jobs/<id>/voice-slots` with `{"scheme":"male_first"}` reapplies that default. The workbench asks once before Edge synthesis until `voices_confirmed` is set. Before Edge TTS, `clean_tts_text` strips a leading `>>` turn marker and short stage directions such as `[Music]` or `（笑）`. If nothing speakable remains (for example a bare `？`), the engine writes 0.12 s of silence and does not call Edge. Selected style is part of every synthesis cache identity. Unchanged lines keep their previous cache key.

### 长访谈的声纹参数

任务 `config.json` 可设置 `diarization_threshold`（合法范围不含 0 和 2）。缺省时 YouTube 为 0.9，本地文件为 0.5；创建 YouTube 任务会把 0.9 写进 config。这个参数传给隔离的 sherpa worker，仅影响当前任务重新准备译稿时的聚类。数值需要结合原声证据校验，不能通过提高阈值或指定人数来掩盖真实的不同说话人。已完成译稿不会因修改该值自动重算。CLI 声纹缓存的指纹仍写死聚类阈值 0.5，并用 `stitching_version` 作废旧 turns；工作室不读这份缓存。

2026-10-18 实测 YouTube MM-C3JqCXBk：默认阈值发生过度拆分；0.9 能完成整期分析，但仍有短句分类错误，需要对照清晰参考原声复核。此参数不代表自动声纹识别质量已达到商业配音服务。
